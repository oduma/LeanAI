# Release Notes — Phase 4.5: Google Sheets Import

**Released:** 2026-05-12
**Branch:** main
**Tests:** 79 / 79 passing

## What's New

### Import Historical Weight Data from Google Sheets

Users can now migrate their entire weight history from a Google Sheets spreadsheet directly into LeanAI. The import wizard is accessible from the **Settings** tab under **DATA IMPORT**.

---

## Feature Details

### 5-Step Import Wizard

A dedicated 5-step modal wizard guides the user through the full import process.

**Step 1 — Sign in with Google**
- Secure OAuth 2.0 Authorization Code flow with PKCE (no client secret).
- Opens Google's consent screen in a Chrome Custom Tab via `WebAuthenticator`.
- Refresh token stored in `SecureStorage`; subsequent imports skip sign-in automatically (silent refresh).

**Step 2 — Select Spreadsheet**
- Lists all Google Sheets files from the user's Drive.
- Tap any row to proceed.

**Step 3 — Map Columns**
- Three dropdowns: Date column (required), Weight column (required), Notes column (optional).
- Automatically pre-selects the most likely column for each field by matching header names.
- Unit toggle: **Metric (kg)** or **Imperial (lbs)** — all values are converted to kg before storage.

**Step 4 — Confirm Before Import**
- Full-page warning listing every consequence before a single byte is written:
  - Goal period will be updated.
  - Starting weight will be updated.
  - Ideal weight line will be recalculated.
  - Existing entries with a valid imported weight will be overwritten.
  - Target weight is **not** changed.

**Step 5 — Import Summary**
After the import completes, the summary screen shows:

| Metric | Meaning |
|--------|---------|
| Dates found in spreadsheet | Total rows with a parseable date |
| Days on ideal weight line | Full span from first weighted day to last dated row |
| Dates with a recorded weight | Rows that also have a weight value |
| Weight entries saved | Actual weight records written to the database |
| Rows that could not be parsed | Only shown when > 0 |

---

### Disconnect Google Account

A **Disconnect Google Account** row appears in Settings whenever a Google refresh token is stored. Tapping it clears the token; the next import will require re-authentication.

## Import Logic

### Two-Phase Import

The import runs in two distinct phases:

**Phase 1 — Date range and ideal path**
All rows with a valid date — including future-dated rows with no weight recorded yet — are used to define the goal period. This means if your spreadsheet runs to the end of the year, the ideal weight line extends to that date automatically.

- `GoalStartDate` = first date in the sheet that has a weight recorded
- `GoalEndDate` = last date in the sheet (regardless of whether a weight is recorded)
- The ideal weight line is regenerated across this full span using the first imported weight as the starting point and the existing target weight unchanged.

**Phase 2 — Actual weight entries**
Only rows where the weight cell is non-empty and greater than zero are written to the `DailyActualWeight` table.

### Overwrite Rule
| Condition | Behaviour |
|-----------|-----------|
| Date exists in app, imported weight > 0 | Existing entry overwritten |
| Date exists in app, imported weight is 0 or blank | Existing entry preserved |
| Date does not exist in app, imported weight > 0 | New entry inserted |
| Date does not exist in app, imported weight is 0 or blank | No entry created |

## Scope Changes from Original Plan

| # | What changed | Why |
|---|-------------|-----|
| SC-1 | `lastDate` is the last *dated row*, not the last *weighted row* | Future rows without weights must anchor the ideal weight line end date |
| SC-2 | Two-phase import instead of skip/import | User needed all dates to define the goal period even when weight isn't recorded |
| SC-3 | `ImportSummaryDto` expanded from 3 to 4 counts | More informative summary requested |
| SC-4 | Step 5 UI redesigned into two sections | Reflects the two-phase semantics clearly |
| SC-5 | Sheets range capped at `"2:401"` | Google Sheets API rejects `int.MaxValue` as a row index |
| SC-6 | Date parsing extended (16 formats + `DateTime.TryParse` fallback) | Locale-specific formats returned by the API weren't matched by the original 6 formats |
| SC-7 | `IGoogleTokenStorage` interface extracted | Infrastructure layer has no access to `SecureStorage`; needed MAUI-layer implementation |
| SC-8 | Android OAuth client type required | Google blocks custom URI schemes on Web-type OAuth clients |
| SC-9 | `CurrentStep = 5` moved before the import call | Spinner was only visible after import completed — no visual feedback during operation |

## One-Time Setup Required (per developer / device)

1. Google Cloud Console: create an **Android** OAuth 2.0 client with your debug SHA-1 and package name `com.leanai.app`.
2. Enable **Custom URI scheme** in the Android client's Advanced Settings.
3. Add your Google account as a **Test User** on the OAuth consent screen (until the app completes Google verification).
4. The reverse client ID (`com.googleusercontent.apps.{client_id}`) must match `DataScheme` in `WebAuthCallbackActivity.cs` and the constants in `ImportWizardViewModel.cs`.
